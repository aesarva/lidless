# Lidless 0.4.0 — автообновления и доработки помощника

Дата: 2026-10-24
Статус: дизайн согласован в чате, ожидает ревью спецификации
Ветка: `feature/auto-updates` (от `develop`)
Образец: ochre, `docs/superpowers/specs/2026-10-24-auto-updates-design.md` в соседнем репозитории

## 1. Цель

Две части одного релиза:

1. Lidless сам узнаёт о новой версии, показывает её в панели и синей точкой на значке и ставит одним нажатием. Идущий эфир, включая режим крышки, переживает перезапуск.
2. Закрыты все доработки, отложенные при выпуске 0.3.0 (§8).

Критерии успеха:
- Через сутки после публикации релиза запущенная копия показывает строку «Доступна версия X» и синюю точку.
- Одно нажатие «Установить и перезапустить» приводит к запущенной новой версии без окон Sparkle и без второго клика. Если шёл эфир, он продолжается с тем же концом, экраном и режимом крышки.
- Обновление без нашей подписи EdDSA или без подписи Developer ID не устанавливается.
- После обновления помощник перерегистрируется сам (новая сборка), режим крышки работает без действий пользователя.
- Фоновая проверка — один HTTP-запрос раз в сутки, без данных о системе; отключается в настройках.

Не цели: дельта-обновления, бета-канал, «Пропустить версию», список изменений внутри приложения, обновление установленной 0.3.0 (в ней нет обновлятеля; её пользователи один раз скачивают 0.4.0 вручную).

## 2. Подход

Sparkle 2 (ровно 2.10.0) со своим интерфейсом через `SPUUserDriver`, как в ochre. Sparkle отвечает за ленту, скачивание, проверку подписей (EdDSA и Apple code signing), замену бандла и перезапуск; Lidless — за показ состояния, ответы Sparkle и продолжение эфира.

Отклонены: стандартные окна Sparkle (отдельное окно и два клика, чужие визуальному миру «On Air») и свой обновлятель (замена запущенного приложения, App Translocation, права на `/Applications` и откат — самим).

### 3.1 `UpdateState`

Как в ochre, без изменений по смыслу:

```swift
public enum UpdateState: Equatable, Sendable {
    case idle, checking, upToDate
    case available(version: String, notesURL: URL?)
    case downloading(version: String, progress: Double?)
    case installing(version: String)
    case failed(message: String)
    case needsMove
}
```

События и переходы — ochre §3.1 вместе с `locationUnsupported` и `backgroundCheckSucceeded`. `showsBadge` — `available`, `downloading`, `installing`.

### 3.2 Драйвер

Как в ochre §3.2: `showReadyToInstallAndRelaunch` сразу отвечает `.install`; ошибки и «обновлений нет» подтверждаются сразу; `showUpdateInFocus` открывает панель; запрос разрешения отвечает «проверять автоматически, без профиля системы».

### 3.3 Интерфейс

- Строка в панели (между переключателями и подвалом, 320pt колонки, обе локали переносятся, не расширяя колонку):
  - `available` — «● Доступна версия 0.4.1 · Что нового · [Установить и перезапустить]»;
  - `downloading` — «Скачивание 0.4.1» и полоса прогресса (неопределённая при `nil`);
  - `installing` — «Установка…»;
  - `failed` — «Не удалось обновить» и «Повторить»;
  - `checking` — «Проверка обновлений…» (только после ручной проверки или «Повторить»);
  - `needsMove` — «Перенеси Lidless в Программы, чтобы обновлять его»;
  - `idle` и `upToDate` — строки нет (`upToDate` видна только в настройках).
- Точка на значке — `NSColor.controlAccentColor`, пока `showsBadge`. Оранжевая точка «нужно внимание» важнее: если нужны обе, рисуется оранжевая. Красный по-прежнему только эфир. Точка цветная, значит значок в этом состоянии не шаблонный, как сейчас у `attention`.
- VoiceOver значка дополняется «доступно обновление».
- Быстрое меню: «Установить версию 0.4.1» при `available`.
- Настройки → Основные: «Проверять обновления автоматически», «Проверить сейчас» с подписью результата («Установлена последняя версия», текст ошибки).
- О программе: «Версия 0.4.0 (сборка N)».
- Новые строки — с русским переводом в `Localizable.xcstrings`; вид — по DESIGN.md (кнопка установки — не красная).

## 4. Продолжение эфира через обновление

- `UpdateController` в `updaterWillRelaunchApplication(_:)` (делегат Sparkle) сохраняет `ResumeSnapshot` в `UserDefaults` (ключ `resumeAfterUpdate`), только если идёт сессия:
  - `savedAt`, `startedAt`, `endsAt` (nil — бессрочно), `keepDisplayOn`;
  - желание режима крышки берётся из настроек (оно и так сохраняется), снимок хранит `lidModeEnabledAt` — чтобы лимит «время с закрытой крышкой на батарее» не обнулился.
- При запуске снимок читается и удаляется один раз (до любого старта сессии, вместо «стартовать сессию при запуске», если восстановление состоялось). Восстанавливается, если:
  - `savedAt` не старше 120 с (иначе — обычный запуск, снимок игнорируется);
  - `endsAt` в будущем или nil.
- Восстановление — обычный старт сессии с переданными `startedAt`, `endsAt`, `keepDisplayOn`, `lidModeEnabledAt`; правила защиты проверяются как при любом старте (низкий заряд не даст стартовать). Режим крышки включается обычным путём `enableLidMode(keepingStart: true)`.
- Перерыв — несколько секунд при открытой крышке (установку запускает нажатие в панели), поэтому заснуть Mac не успевает. Пока нового приложения нет, демон возвращает обычный сон, как при любом выходе.

## 5. Помощник и обновление

- Демон сообщает версию и номер сборки (§8.8). Новое приложение видит другую сборку (или не может декодировать ответ старого демона) и перерегистрирует его — существующий путь, проверенный вживую в 0.3.0.
- Старый демон, запущенный из заменённого бандла, получает SIGTERM при перерегистрации и возвращает сон сам.

## 6. Сборка, подпись и релиз

- `project.yml`: пакет `Sparkle` (`url: https://github.com/sparkle-project/Sparkle`, `exactVersion: 2.10.0`), зависимость цели `Lidless` с встраиванием в `Contents/Frameworks`.
- `build-app.sh` переподписывает вложенный код Sparkle тем же `SIGN_FLAGS`, изнутри наружу: `XPCServices/Installer.xpc`, `XPCServices/Downloader.xpc` (`--preserve-metadata=entitlements`), `Autoupdate`, `Updater.app`, `Sparkle.framework`; затем демон и приложение, затем `codesign --verify --deep --strict`.
- `Info.plist`: `SUFeedURL` = `https://github.com/aesarva/lidless/releases/latest/download/appcast.xml`, `SUPublicEDKey`, `SUEnableAutomaticChecks` = `YES`, `SUScheduledCheckInterval` = `86400`.
- `CFBundleVersion` — число коммитов (как сейчас); Sparkle сравнивает по нему, релиз собирается с `develop`, слитого в `main`.
- Отладка: параметр запуска `-UpdateFeedURL <url>` (argument domain) через `feedURLString(for:)`. Работает и в Release: подписи EdDSA и Developer ID проверяются всё равно.
- Ключ EdDSA создаёт пользователь один раз: `generate_keys` (приватный — в связке ключей), резервная копия `generate_keys -x <файл>` вне Mac. Публичный — в Info.plist.
- `scripts/make-appcast.sh <dmg> <версия> <сборка>` печатает `appcast.xml` из одного элемента (`sparkle:version`, `shortVersionString`, `pubDate`, `minimumSystemVersion` = `14.0`, `releaseNotesLink` на страницу релиза, `enclosure` на `Lidless-<версия>.dmg` с подписью и длиной от `sign_update`). `release.sh` вызывает его после нотаризации и скрепления DMG и проверяет `xmllint`.
- К релизу на GitHub прикладываются `Lidless-<версия>.dmg`, `Lidless.dmg` и `appcast.xml`.

## 7. Ошибки обновления

- Нет сети при фоновой проверке — молча, следующая по расписанию.
- Ошибка ручной проверки, скачивания или установки — `failed` с текстом Sparkle и «Повторить».
- Неверная подпись — Sparkle отказывает, показ как выше.
- Запуск из образа DMG или после App Translocation — `needsMove`.

## 8. Доработки помощника

1. **Remove не оставляет `disablesleep 1` без хозяина.** Перед `unregister` режим крышки выключается и сброс должен быть подтверждён. Если не подтверждён — удаление не выполняется, вкладка Helper показывает «Не удалось вернуть обычный сон — помощник не удалён», режим крышки возвращается как был (`restoreAfterFailedRemoval`).
2. **Сброс остатков 0.2.0 не гоняется с новым помощником.** Пока фоновый `LegacySleepReset` не закончился, режим крышки не включается: ждёт молча, как ожидание одобрения, и включается сам по окончании (тот же путь, что `helperDidChange`).
3. **Выключение режима крышки не блокирует главный поток.** Сброс выполняется в фоне; переключатель и состояние сессии сразу «выкл». Пока сброс не подтверждён, действует `recoveryPending` (повтор по опросу). Неудача — оранжевая точка и одно уведомление, как сейчас. Путь §8.1 ждёт подтверждения асинхронно.
4. **Сбой удаления маркера после подтверждённого 0.** После успешной записи 0 `SleepGuard` переводит маркер в `.stale` до `store.remove()`, так что повтор только удаляет файл и больше не пишет 0. `recoverAtStart`: маркер есть и `disablesleep` = 0 — `.stale` (удалить без записи); `disablesleep` = 1 — `.owned` (как сейчас).
5. **Неподписанная сборка с сохранённым режимом крышки** не шлёт уведомление и не зажигает точку при каждой сессии: `.unsigned` ждёт молча, как `.notInstalled`; подпись «нужна подписанная сборка» остаётся.
6. **Версия на вкладке Helper:** «Работает — версия 0.4.0 (сборка N)» из ответа демона.
7. **Здоровый демон не перерегистрируется.** Перерегистрация — только когда: версия или сборка не совпадает; соединение оборвано без ответа (`HelperError.rejected`); ответа нет по тайм-ауту дважды подряд (повтор через 1 с). Ответ демона с ошибкой (`pmset -g` не сработал) — это ошибка помощника без перерегистрации. Для этого клиент различает тайм-аут (`HelperError.timedOut`) и ответ с ошибкой.
8. **Номер сборки демона.** `info` отвечает ещё и `CFBundleVersion` демона; несовпадение со сборкой приложения — повод перерегистрировать (раз за запуск, как сейчас). Так новый plist подхватывается любой новой сборкой, включая dev. Ответ старого демона с другой сигнатурой не декодируется — это `rejected`, тоже перерегистрация.

## 9. Тесты и проверка

- LidlessCore (Swift Testing, фейки как сейчас):
  - `UpdateStateTests` — переходы ochre, включая фоновую ошибку → `idle`, ручную → `failed`, неизвестную длину, ограничение доли, `needsMove`, `backgroundCheckSucceeded`.
  - `ResumeSnapshotTests` — свежий / старше 120 с / истёкший `endsAt` / бессрочный; снимок читается один раз.
  - `SessionController` — восстановление сессии с `startedAt`, `endsAt`, `lidModeEnabledAt`; низкий заряд не даёт восстановить.
  - По §8: Remove не вызывает `unregister` после неудачного сброса; режим крышки ждёт окончания сброса 0.2.0; выключение не вызывает синхронно `lid.disable()` на главном потоке; повтор после сбоя удаления маркера не пишет 0; `recoverAtStart` при 0; `.unsigned` без уведомления; ошибка-ответ без перерегистрации, двойной тайм-аут — с перерегистрацией; несовпадение сборки — перерегистрация.
- Вживую на подписанной сборке, до релиза:
  1. Старая сборка N и новая N+1 (подписанный DMG + appcast) раздаются с `127.0.0.1`; старая запущена с `-UpdateFeedURL`, идёт эфир с режимом крышки.
  2. Появились строка и синяя точка; «Установить» скачивает и перезапускает; номер сборки N+1; эфир продолжается с тем же концом, режим крышки снова включён, демон перерегистрирован (сборка N+1 на вкладке Helper).
  3. DMG с испорченной подписью отклоняется — «Не удалось обновить».
  4. §8.1, §8.3, §8.8 — вживую: Remove при недоступном демоне не снимает регистрацию; выключение при ошибке помощника не подвешивает меню; новая сборка без смены версии перерегистрирует демона.
- Ревью: каждую задачу — ревьюер Claude и Codex (`gpt-6-astra`); в конце — обе стороны по всей ветке.
