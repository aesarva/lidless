# Lidless 0.4.0 — автообновления и доработки помощника

Дата: 2026-10-24
Статус: дизайн согласован в чате; исправлен по ревью Codex; ожидает ревью спецификации
Ветка: `feature/auto-updates` (от `develop`)
Образец: ochre, `docs/superpowers/specs/2026-10-24-auto-updates-design.md` в соседнем репозитории

## 1. Цель

Две части одного релиза:

1. Lidless сам узнаёт о новой версии, показывает её в панели и синей точкой на значке и ставит одним нажатием. Идущий эфир, включая режим крышки, переживает перезапуск.
2. Закрыты все доработки, отложенные при выпуске 0.3.0 (§8).

Критерии успеха:
- Через сутки после публикации релиза запущенная копия показывает строку «Доступна версия X» и синюю точку.
- Одно нажатие «Установить и перезапустить» приводит к запущенной новой версии без окон Sparkle и без второго клика. Если шёл эфир, он продолжается с тем же концом, экраном и режимом крышки.
- Обновление без нашей подписи EdDSA не устанавливается. Sparkle 2.10 при верной EdDSA допускает смену подписи кода (ротацию), поэтому гарантию «только Developer ID нашей команды» даёт выпуск: `release.sh` не создаёт ленту, если приложение или демон не подписаны Developer ID команды `6H45P75YYV` или не прошли `spctl` (§6).
- После обновления помощник перерегистрируется сам (новая сборка), режим крышки работает без действий пользователя.
- Фоновая проверка — одно чтение ленты раз в сутки (с переадресациями GitHub), без данных о системе; заметки к выпуску не скачиваются; отключается в настройках.

Не цели: дельта-обновления, бета-канал, «Пропустить версию», список изменений внутри приложения, обновление установленной 0.3.0 (в ней нет обновлятеля; её пользователи один раз скачивают 0.4.0 вручную).

## 2. Подход

Sparkle 2 (ровно 2.10.0) со своим интерфейсом через `SPUUserDriver`, как в ochre. Sparkle отвечает за ленту, скачивание, проверку подписей (EdDSA и Apple code signing), замену бандла и перезапуск; Lidless — за показ состояния, ответы Sparkle и продолжение эфира.

Отклонены: стандартные окна Sparkle (отдельное окно и два клика, чужие визуальному миру «On Air») и свой обновлятель (замена запущенного приложения, App Translocation, права на `/Applications` и откат — самим).

### 3.1 `UpdateState`

Как в ochre, без изменений по смыслу:

```swift
public enum UpdateState: Equatable, Sendable {
    case idle, checking, upToDate
    case available(version: String, notesURL: URL?)
    case downloading(version: String, progress: Double?)
    case installing(version: String)
    case failed(message: String)
    case needsMove
}
```

События и переходы — ochre §3.1 вместе с `locationUnsupported` и `backgroundCheckSucceeded`. `showsBadge` — `available`, `downloading`, `installing`.

### 3.2 Драйвер

Как в ochre §3.2, кроме: `showReadyToInstallAndRelaunch` отвечает `.install` сразу, только если крышка открыта, иначе ответ откладывается до открытия (§4); делегат `updater(_:shouldDownloadReleaseNotesForUpdate:)` возвращает `false`; ошибки и «обновлений нет» подтверждаются сразу; `showUpdateInFocus` открывает панель; запрос разрешения отвечает «проверять автоматически, без профиля системы».

### 3.3 Интерфейс

- Строка в панели (между переключателями и подвалом, 320pt колонки, обе локали переносятся, не расширяя колонку):
  - `available` — «● Доступна версия 0.4.1 · Что нового · [Установить и перезапустить]»;
  - `downloading` — «Скачивание 0.4.1» и полоса прогресса (неопределённая при `nil`);
  - `installing` — «Установка…»; если установка ждёт открытия крышки — «Установится, когда откроешь крышку»;
  - `failed` — «Не удалось обновить» и «Повторить»;
  - `checking` — «Проверка обновлений…» (только после ручной проверки или «Повторить»);
  - `needsMove` — «Перенеси Lidless в Программы, чтобы обновлять его»;
  - `idle` и `upToDate` — строки нет (`upToDate` видна только в настройках).
- Точка на значке — `NSColor.controlAccentColor`, пока `showsBadge`. Оранжевая точка «нужно внимание» важнее: если нужны обе, рисуется оранжевая. Красный по-прежнему только эфир. Точка цветная, значит значок в этом состоянии не шаблонный, как сейчас у `attention`.
- VoiceOver значка дополняется «доступно обновление».
- Быстрое меню: «Установить версию 0.4.1» при `available`.
- Настройки → Основные: «Проверять обновления автоматически», «Проверить сейчас» с подписью результата («Установлена последняя версия», текст ошибки).
- О программе: «Версия 0.4.0 (сборка N)».
- Новые строки — с русским переводом в `Localizable.xcstrings`; вид — по DESIGN.md (кнопка установки — не красная).

## 4. Продолжение эфира через обновление

- **Только при открытой крышке.** Выход старого приложения возвращает обычный сон (утверждения снимаются, демон сбрасывает `disablesleep`). Поэтому драйвер отвечает Sparkle `.install` (§3.2), только когда крышка открыта; если её закрыли во время скачивания или Mac работает в clamshell, установка ждёт открытия крышки. Так за перерыв в несколько секунд Mac заснуть не может, и интервал «закрыто на батарее» к перезапуску уже сброшен открытием крышки.
- `UpdateController` в `updaterWillRelaunchApplication(_:)` (делегат Sparkle) сохраняет `ResumeSnapshot` в `UserDefaults` (ключ `resumeAfterUpdate`), только если идёт сессия:
  - `savedAt`, `startedAt`, `endsAt` (nil — бессрочно), `keepDisplayOn`;
  - состояние режима крышки: был ли он включён (`lidModeActive`), причина паузы (`lidModeSuspendedReason`) и `lidModeEnabledAt`.
- При запуске снимок читается и удаляется один раз, до любого старта сессии; если восстановление состоялось, «стартовать сессию при запуске» не срабатывает. Восстанавливается, если `savedAt` не старше 120 с и `endsAt` в будущем или nil; иначе — обычный запуск.
- Восстановление — обычный старт сессии (низкий заряд не даст стартовать) с переданными `startedAt`, `endsAt`, `keepDisplayOn`. Режим крышки:
  - была пауза по правилу защиты — сессия восстанавливается с той же паузой; режим крышки не включается сам (как сейчас: снять паузу может только пользователь);
  - был включён или ждал помощника — сессия получает паузу `.helperUnavailable` с прежним `lidModeEnabledAt`, и режим крышки включает существующий путь `retryHelperSuspendedLidMode`, который сначала проверяет все правила защиты по свежим показаниям (`safetyBlock`);
  - был выключен — остаётся выключенным.
- Если новая версия не запустилась, Mac просто возвращается к обычному сну — безопасное состояние.

## 5. Помощник и обновление

- Демон сообщает версию и номер сборки (§8.8). Новое приложение видит другую сборку (или не может декодировать ответ старого демона) и перерегистрирует его — существующий путь, проверенный вживую в 0.3.0.
- Старый демон, запущенный из заменённого бандла, получает SIGTERM при перерегистрации и возвращает сон сам.

## 6. Сборка, подпись и релиз

- `project.yml`: пакет `Sparkle` (`url: https://github.com/sparkle-project/Sparkle`, `exactVersion: 2.10.0`), зависимость цели `Lidless` с встраиванием в `Contents/Frameworks`.
- Hardened runtime с library validation не загрузит Sparkle.framework в ad-hoc сборке (нет Team ID). Поэтому `--options runtime` (и `--timestamp`) — только при подписи Developer ID; ad-hoc сборки (`SIGN_IDENTITY=-`, `make run`/Debug) подписываются без runtime, в `project.yml` `ENABLE_HARDENED_RUNTIME` только для Release. Проверка: ad-hoc сборка действительно запускается.
- `build-app.sh` переподписывает вложенный код Sparkle тем же `SIGN_FLAGS`, изнутри наружу: `XPCServices/Installer.xpc`, `XPCServices/Downloader.xpc` (`--preserve-metadata=entitlements`), `Autoupdate`, `Updater.app`, `Sparkle.framework`; затем демон и приложение, затем `codesign --verify --deep --strict`.
- `Info.plist`: `SUFeedURL` = `https://github.com/aesarva/lidless/releases/latest/download/appcast.xml`, `SUPublicEDKey`, `SUEnableAutomaticChecks` = `YES`, `SUScheduledCheckInterval` = `86400`.
- `CFBundleVersion` — число коммитов (как сейчас); Sparkle сравнивает по нему, релиз собирается с `develop`, слитого в `main`.
- Отладка: параметр запуска `-UpdateFeedURL <url>` (argument domain) через `feedURLString(for:)`. Работает и в Release: подписи EdDSA и Developer ID проверяются всё равно.
- Ключ EdDSA создаёт пользователь один раз: `generate_keys` (приватный — в связке ключей), резервная копия `generate_keys -x <файл>` вне Mac. Публичный — в Info.plist.
- `scripts/make-appcast.sh <dmg> <версия> <сборка>` печатает `appcast.xml` из одного элемента (`sparkle:version`, `shortVersionString`, `pubDate`, `minimumSystemVersion` = `14.0`, `releaseNotesLink` на страницу релиза, `enclosure` на `Lidless-<версия>.dmg` с подписью и длиной от `sign_update`). `release.sh` вызывает его после нотаризации и скрепления DMG и проверяет `xmllint`. До этого `release.sh` проверяет, что приложение, демон и Sparkle подписаны Developer ID с Team ID `6H45P75YYV`, а приложение и DMG приняты `spctl`; иначе лента не создаётся. В ленте нет `releaseNotesLink`: ссылка «Что нового» — `<link>` элемента (страница релиза), она открывается в браузере только по нажатию.
- К релизу на GitHub прикладываются `Lidless-<версия>.dmg`, `Lidless.dmg` и `appcast.xml`.

## 7. Ошибки обновления

- Нет сети при фоновой проверке — молча, следующая по расписанию.
- Ошибка ручной проверки, скачивания или установки — `failed` с текстом Sparkle и «Повторить».
- Неверная подпись — Sparkle отказывает, показ как выше.
- Запуск из образа DMG или после App Translocation — `needsMove`.

## 8. Доработки помощника

1. **Remove не оставляет `disablesleep 1` без хозяина.** Перед `unregister` режим крышки выключается (§8.3), и сброс должен быть подтверждён демоном: `info` сообщает, владеет ли демон `disablesleep` (маркер `.owned`, §8.8), и удаление идёт, только если не владеет. Отсутствие локального удержания подтверждением не считается. Если не подтверждено или демон не отвечает — удаление не выполняется, вкладка Helper показывает «Не удалось вернуть обычный сон — помощник не удалён», режим крышки возвращается как был (`restoreAfterFailedRemoval`).
2. **Сброс остатков 0.2.0 не гоняется с новым помощником.** Пока фоновый `LegacySleepReset` не закончился, режим крышки не включается: ждёт молча, как ожидание одобрения, и включается сам по окончании (тот же путь, что `helperDidChange`).
3. **Вызовы помощника не блокируют главный поток: желаемое состояние вместо отдельных команд.** `SessionController` не отправляет «включить»/«выключить», а сообщает `LidSleepService` желаемое состояние удержания (`wanted: Bool`). Сервис на одной последовательной очереди приводит демона к последнему желаемому: включает, выключает, после ошибки повторяет по опросу; на главный актор сообщает подтверждённое состояние (`held`, `pending`, ошибка). Устаревшие ответы не важны по построению: после каждого шага сервис сверяется с текущим желанием. Следствия:
   - остановка сессии, пауза по правилу защиты или выключение во время незавершённого включения просто меняют желание на «нет» — сервис снимет удержание, когда включение дойдёт;
   - желание считается в `SessionController` из сессии, настройки, паузы и `safetyBlock` по свежим показаниям — правила защиты действуют и пока включение в пути; подтверждённое «держит» применяется, только если желание всё ещё «да»;
   - разрыв соединения (`connectionLost`) делает подтверждённое состояние «не держит» независимо от того, дошёл ли ответ включения (поколения соединений запоминаются и после разрыва); при желании «да» сервис включает снова;
   - выключение: переключатель и сессия сразу «выкл»; успешный ответ демона на выключение снимает наше удержание. После ошибки — «сброс ожидается», пока демон не подтвердит свежим `info` (не из кеша), что не владеет `disablesleep`; повтор по опросу независимо от сессии; устаревшее подтверждение (пришедшее после нового желания) отбрасывается; `recoverIfNeeded()` удаляется. Неудача — оранжевая точка и одно уведомление, как сейчас;
   - включение отправляется только проверенному демону (`.installed`); выключение — и при `.error`/`.checking`;
   - правила защиты действуют и на ещё не подтверждённое включение: пауза фиксируется и остаётся после остывания, как для активного режима;
   - включение: строка режима крышки показывает «включается…» до подтверждения; когда удержание подтверждено при уже закрытой крышке, экран гаснет сразу (не ждёт следующего закрытия);
   - сброс остатков 0.2.0 (§8.2) — первая работа на этой же очереди.
4. **Сбой удаления маркера после подтверждённого 0.** После успешной записи 0 `SleepGuard` переводит маркер в `.stale` до `store.remove()`, так что повтор только удаляет файл и больше не пишет 0. `recoverAtStart`: маркер есть и `disablesleep` = 0 — `.stale` (удалить без записи); `disablesleep` = 1 — `.owned` (как сейчас).
5. **Неподписанная сборка с сохранённым режимом крышки** не шлёт уведомление и не зажигает точку при каждой сессии: `.unsigned` ждёт молча, как `.notInstalled`; подпись «нужна подписанная сборка» остаётся.
6. **Версия на вкладке Helper:** «Работает — версия 0.4.0 (сборка N)» из ответа демона.
7. **Здоровый демон не перерегистрируется.** Перерегистрация — только когда: версия или сборка не совпадает; соединение оборвано без ответа (`HelperError.rejected`); ответа нет по тайм-ауту дважды подряд (повтор через 1 с). Ответ демона с ошибкой (`pmset -g` не сработал) — это ошибка помощника без перерегистрации. Для этого клиент различает тайм-аут (`HelperError.timedOut`) и ответ с ошибкой.
8. **Номер сборки и владение в `info`.** `info` отвечает ещё `CFBundleVersion` демона и владеет ли он `disablesleep` (маркер `.owned`); номер сборки несовпадение со сборкой приложения — повод перерегистрировать (раз за запуск, как сейчас). Так новый plist подхватывается любой новой сборкой, включая dev. Ответ старого демона с другой сигнатурой не декодируется — это `rejected`, тоже перерегистрация.
9. **Перерегистрация ждёт ухода старого демона.** `unregister(completionHandler:)` вместо синхронного `unregister()`; `register()` — только после обработчика (Apple называет его безопасной точкой для повторной регистрации), ожидание не дольше 10 с. Если `register()` всё же не удался, состояние «перерегистрация не завершена» сохраняется и повторяется при следующем обновлении статуса (а не запрещается флагом «раз за запуск»); вкладка Helper и строка режима крышки показывают ошибку. Режим крышки возвращается, только когда новый демон ответил на `info` с совпадающими версией и сборкой: до первой такой проверки текущей регистрации статус — `.checking` (ждёт молча, как одобрения), а не `.installed`. Если `unregister` не подтвердился за 10 с, `register()` не вызывается вовсе — следующая попытка начинается снова с ожидания `unregister`.

## 9. Тесты и проверка

- LidlessCore (Swift Testing, фейки как сейчас):
  - `UpdateStateTests` — переходы ochre, включая фоновую ошибку → `idle`, ручную → `failed`, неизвестную длину, ограничение доли, `needsMove`, `backgroundCheckSucceeded`.
  - `ResumeSnapshotTests` — свежий / старше 120 с / истёкший `endsAt` / бессрочный; снимок читается один раз.
  - `SessionController` — восстановление сессии с `startedAt`, `endsAt`, `lidModeEnabledAt`; низкий заряд не даёт восстановить.
  - По §4: снимок с паузой по правилу защиты не включает режим крышки; включённый режим восстанавливается через проверку всех правил защиты; закрытая крышка откладывает ответ `.install`.
  - По §8: Remove не вызывает `unregister` после неудачного сброса и при `owned` = true; режим крышки ждёт окончания сброса 0.2.0; выключение не вызывает синхронно `lid.disable()` на главном потоке; быстрые выкл→вкл и стоп→старт с задержанными ответами не снимают новое удержание; устаревшее завершение не меняет состояние; «сброс ожидается» опрашивается и при идущей сессии; повтор после сбоя удаления маркера не пишет 0; `recoverAtStart` при 0; `.unsigned` без уведомления; ошибка-ответ без перерегистрации, двойной тайм-аут — с перерегистрацией; несовпадение сборки — перерегистрация; `register()` только после обработчика `unregister`; неудачная перерегистрация повторяется.
- Вживую на подписанной сборке, до релиза:
  1. Старая сборка N и новая N+1 (подписанный DMG + appcast) раздаются с `127.0.0.1`; старая запущена с `-UpdateFeedURL`, идёт эфир с режимом крышки.
  2. Появились строка и синяя точка; «Установить» скачивает и перезапускает; номер сборки N+1; эфир продолжается с тем же концом, режим крышки снова включён, демон перерегистрирован (сборка N+1 на вкладке Helper).
  3. DMG с испорченной подписью отклоняется — «Не удалось обновить».
  4. Крышку закрыли во время скачивания — установка ждёт открытия, Mac не засыпает.
  5. Ad-hoc сборка (`make app` без сертификата) запускается и загружает Sparkle.
