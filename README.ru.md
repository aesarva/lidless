## Зачем Lidless

Большинство утилит против сна умеют одно: «не спать, пока крышка открыта». Lidless сделан для случаев, когда ты действительно отходишь от компьютера:

- **Работает с закрытой крышкой.** Закрываешь крышку — экран гаснет, а Mac продолжает сборку, загрузку, рендер, работу AI-агента, SSH-сессию или трансляцию по AirPlay. Если подключён внешний монитор, Lidless экраны не трогает.
- **Сам себя страхует.** Сессия останавливается при низком заряде, режим крышки ставится на паузу, если Mac нагрелся, а лимит времени не даст забытому ноутбуку перегреться в рюкзаке. При критическом нагреве с закрытой крышкой сессия завершается.
- **Никогда не ломает Mac.** Выход из Lidless возвращает обычный сон. Если приложение упадёт или его закроют принудительно, обычный сон вернётся сразу; если Mac перезагрузится посреди сессии, значение сбросится при загрузке. Единственная привилегированная команда, которую может выполнить Lidless, — `pmset -a disablesleep 0|1`.
- **Одно нажатие.** Табличка «В ЭФИРЕ» и есть кнопка: нажал — в эфире, нажал ещё раз — вышел из эфира. Для сессии с таймером на табличке идёт обратный отсчёт, для бессрочной — время в эфире.
- **Честно с первого взгляда.** В эфире значок в строке меню — маленькая горящая красная лампа; с таймером её свет «выгорает» вместе с оставшимся временем. Оранжевая точка значит, что нужно внимание.
- **Нативно и приватно.** SwiftUI + AppKit, универсальная сборка, никаких сетевых запросов, аналитики и аккаунтов.

## Возможности

| | |
|---|---|
| **Сессии** | 15 мин, 1 ч, 3 ч (пресеты настраиваются), *До…* — до заданного времени, или бессрочно (∞). Выбор длительности сразу запускает сессию или перезапускает текущую с новым сроком. |
| **Табличка** | Нажми (или Return), чтобы выйти в эфир и обратно. В эфире горит красным и показывает обратный отсчёт или время в эфире; вне эфира — тёмное стекло. |
| **Экран** | *Экран не гаснет* — экран горит; иначе экран может гаснуть, а Mac бодрствует. |
| **Режим крышки** | Mac работает с закрытой крышкой, экран при закрытии сразу гаснет. Нужно один раз разрешить помощника в «Системных настройках» ([подробнее](#режим-крышки-и-помощник)). |
| **Приборы защиты** | Батарея и нагрев на панели как студийные шкалы, с отмеченным порогом батареи. |
| **Уведомления** | За 5 минут до конца сессии с таймером — с кнопками **+30 мин** и **+1 ч**; и когда правило защиты что-то остановило или поставило на паузу. |
| **Значок в строке меню** | Неброская линия вне эфира; горящая лампа в эфире; по желанию — оставшееся время рядом. |
| **Настройки** | Автозапуск при входе, длительность по умолчанию, пресеты, таймер в строке меню, старт сессии при запуске, пороги защиты, настройка и удаление помощника, язык интерфейса. |
| **Языки** | Русский и английский; переключаются в «Настройки → Основные → Язык» независимо от языка системы. |

### Правила защиты

| Правило | По умолчанию | Что происходит |
|---|---|---|
| Низкий заряд | вкл, 20% (5–50%) | От батареи ниже порога сессия останавливается; ниже порога сессия не запустится. |
| Нагрев | вкл | При *серьёзном* нагреве режим крышки ставится на паузу (сессия идёт); при *критическом* с закрытой крышкой сессия останавливается. |
| Время с закрытой крышкой на батарее | вкл, 4 ч (30 мин–12 ч) | После этого режим крышки ставится на паузу. |

Каждое правило можно выключить или настроить в «Настройки → Защита».

## Установка

1. Скачай `Lidless.dmg` со страницы [Releases](https://github.com/aesarva/lidless/releases) и открой его.
2. Перетащи **Lidless** на ярлык **Applications** и запусти. Приложение живёт только в строке меню (без значка в Dock).

Релизы подписаны Developer ID и нотаризованы Apple, поэтому Lidless открывается как любое другое приложение. Нужна macOS 14 Sonoma или новее, Apple Silicon или Intel.

## Как пользоваться

1. Кликни по значку в строке меню.
2. Нажми табличку **В ЭФИРЕ** — или выбери длительность (15 мин, 1 ч, 3 ч, *До…*, ∞), чтобы стартовать сразу с ней.
3. Хочешь закрыть крышку? Включи **Режим крышки** (в первый раз Lidless попросит разрешить помощника в «Системных настройках» — без пароля).
4. Нажми табличку ещё раз, чтобы выйти из эфира. Выход из Lidless тоже завершает сессию и возвращает обычный сон.

Повторный клик по значку или Esc закрывает панель. Правый клик по значку открывает быстрое меню.

## Режим крышки и помощник

Обычные сессии используют стандартный запрет сна macOS и ничего не требуют. Чтобы Mac не уснул с закрытой крышкой (без внешнего монитора), нужна команда `pmset -a disablesleep 1`, а она требует прав root. Для этого Lidless несёт внутри приложения небольшого помощника-демона и регистрирует его в macOS (`SMAppService`). При первом включении режима крышки macOS покажет уведомление и откроет **Системные настройки → Основные → Объекты входа и расширения**; включи Lidless в разделе **Разрешить в фоновом режиме**. Это делается один раз, без пароля, после чего режим крышки включается сам.

| Путь | Назначение |
|---|---|
| `Lidless.app/Contents/MacOS/LidlessHelper` | демон-помощник; работает от root, macOS запускает его по требованию и при загрузке |
| `Lidless.app/Contents/Library/LaunchDaemons/io.github.aesarva.Lidless.helper.plist` | описание задачи launchd, которое регистрирует `SMAppService` |
| `/Library/Application Support/Lidless/sleep-owned` | файл состояния; существует, только пока `disablesleep` включил помощник |

Режим крышки привязан к живому соединению Lidless с помощником. Если Lidless закрылся, упал или закрыт принудительно, помощник сразу возвращает обычный сон. Если Mac перезагрузился посреди сессии, помощник при загрузке видит `sleep-owned` и сбрасывает `disablesleep`. Если выключить помощника в «Объектах входа», обычный сон вернётся, а в значке появится оранжевая точка. Значение `disablesleep`, выставленное тобой вручную, Lidless не трогает.

Когда крышка закрывается в режиме крышки, Lidless гасит экран (`pmset displaysleepnow`, права не нужны) и не даёт Mac уснуть; когда крышка открывается, снова действует твой выбор для экрана.

### Модель безопасности

- **Одна команда.** Единственное привилегированное действие помощника — `pmset -a disablesleep 0|1`. Кроме выбора «вкл/выкл», приложение не передаёт ему ни путей, ни аргументов.
- **Проверка подписи в обе стороны.** Помощник принимает соединения только от Lidless, подписанного той же командой Developer ID, что и он сам, а Lidless подключается только к помощнику с подписью этой команды. Сборка без команды (ad-hoc) отклоняется с обеих сторон.
- **Сброс при разрыве и при загрузке.** Обычный сон возвращается, когда соединение закрыто, а после перезагрузки — при загрузке.
- **Один путь запуска.** Запускай Lidless из одного места (например, `/Applications`): macOS привязывает регистрацию к пути бандла.
- **Если помощник сломается или его выключат** (например, в «Объектах входа») при включённом режиме крышки, обычный сон вернётся, а Lidless покажет оранжевую точку.

### Переход с 0.2.0

Версия 0.2.0 устанавливала правило sudoers, скрипт-сторож с правами root и задачу launchd. Когда ты разрешишь нового помощника, он удалит всё это (и старый файл-маркер) ещё до приёма соединений. Если какие-то файлы останутся, Lidless один раз за запуск повторит попытку, а «Настройки → Помощник» покажут «Помощник 0.2.0 удалён.» или строку с ошибкой. Вручную ничего запускать не нужно.

### Удаление

«Настройки → Помощник → Удалить» (сначала выключит режим крышки, пароль не нужен), затем удалить `Lidless.app`. Если приложение удалено раньше, выключи оставшуюся запись Lidless в **Системных настройках → Основные → Объекты входа и расширения**.

## Приватность

Lidless не делает сетевых запросов, не собирает аналитику и не требует аккаунта. Заряд батареи, источник питания, нагрев и датчик крышки он читает локально, только для правил защиты.

## Сборка из исходников

Нужны Xcode 16 или новее и

```sh
brew install xcodegen shellcheck
```

```sh
make test      # тесты пакета, shellcheck, проверка plist помощника
make build     # сгенерировать проект Xcode и собрать (Debug)
make run       # собрать и запустить Debug-версию
make app       # Release, универсальная сборка (arm64 + x86_64), hardened runtime → build/Lidless.app
make dmg       # make app + dist/Lidless-<VERSION>.dmg без Developer ID (по умолчанию VERSION=0.3.0)
```

Режим крышки работает только в сборках, подписанных Developer ID (релизы или твой собственный сертификат): помощник и приложение проверяют подпись друг друга.

```sh
SIGN_IDENTITY="Developer ID Application: <Имя> (<TEAMID>)" scripts/build-app.sh
```

Неподписанные и ad-hoc сборки выполняют обычные сессии, а для режима крышки показывают «нужна подписанная сборка». Запускай подписанную сборку из одного места (см. [Модель безопасности](#модель-безопасности)).

Подписанный релиз: с сертификатом **Developer ID Application** в связке ключей и один раз сохранёнными данными для нотаризации:

```sh
xcrun notarytool store-credentials Lidless --apple-id <you@example.com> --team-id <TEAMID>
scripts/release.sh 0.3.0     # сборка, подпись, нотаризация приложения и DMG, проверка Gatekeeper
```

Без сертификата: `scripts/release.sh 0.3.0 --unsigned` (или `make dmg`).

## Ручная проверка

Эти проверки требуют настоящего MacBook и сборки, подписанной Developer ID. Пока они не автоматизированы:

1. Первое включение режима крышки: macOS показывает уведомление и открывает «Объекты входа»; после разрешения режим крышки включается сам.
2. Крышка закрыта 5 минут, без зарядки и внешнего монитора: Mac не засыпает, SSH-сессия жива.
3. Принудительно закрыть Lidless в режиме крышки: `pmset -g` показывает `SleepDisabled 0` в течение пары секунд.
4. `sudo kill -9` демону посреди сессии: режим крышки восстанавливается, `SleepDisabled 1` возвращается.
5. Перезагрузка посреди сессии: после загрузки `SleepDisabled 0`.
6. Выключить Lidless в «Объектах входа» посреди сессии: `SleepDisabled 0` и оранжевая точка.
7. `sudo pmset -a disablesleep 1` вручную, затем включить и выключить режим крышки: остаётся 1.
8. Переход с 0.2.0 на этом же Mac: файл sudoers и сторож удалены, задача `app.lidless.watchdog` выгружена.
9. «Настройки → Помощник → Удалить»: демон снят с регистрации, `SleepDisabled 0`.

## Планы

- Автоматические триггеры: не спать, пока запущено приложение, при питании от сети, с монитором или в определённой Wi-Fi сети, во время загрузок, по расписанию.
- Интеграции: глобальная горячая клавиша, URL-схема, CLI, действия для «Команд».
- Статистика и виджеты: история сессий, виджет на рабочем столе, переключатель в Пункте управления.
